# RichAPI GTM Skills — repo conventions

Conventions for anyone — human or agent — working **on** this repo. If you are working
**with** the pack instead, start at [`README.md`](README.md). Contributor workflow,
setup and the review checklist live in [`CONTRIBUTING.md`](CONTRIBUTING.md); this file
is the short version of *why the code is shaped the way it is*.

## The seven laws

These are not style preferences. Each one is enforced by a test, and each exists
because its absence produced a real defect in this codebase.

1. **The catalog is the source of truth for cost and routing.** No credit number is
   ever typed by hand into a skill or a doc. Anything hand-typed is stale within a
   quarter — measured: 16 of 53 surviving endpoints repriced in 4 months,
   `phone_finder` 3 -> 25 credits (8.3x).
2. **The spec is a cost-and-route source, NOT a schema source.** 39 of 68 response
   examples are >=40% the literal string `"example"`; both bulk enrich endpoints have
   no example at all. Field maps come from recorded live fixtures, and the 2026-08-31
   capture proved why: the spec-derived maps were dropping the email, the phone number
   and the verification verdict on every paid call, because the finder endpoints wrap
   their payload in `result` and the scrapers answer different key names entirely.
   Never write a response key into `RESPONSE_MAPS` that does not appear in a recording
   — see [`LIMITATIONS.md`](LIMITATIONS.md) §1. The catalog records which rows are
   evidence:

   - `live_fixture` — 63 of 68. Scalar paths read off a recorded 2xx.
   - `keys_from_spec_example` — 5 of 68. The spec's guess; treat as wrong until recorded.
   - `TODO_no_usable_example` — 0 of 68. Neither.

3. **Every paid call is named and costed before it runs.** No opt-out paid calls, ever
   — including at setup. An unattended run must name a credit ceiling; `--yes` without
   `--budget` is refused, because every gate fires on a *fraction* of a budget and a
   null budget is not "no gate crossed", it is no gate.
4. **Never fabricate an actual.** No endpoint reports its charge: across all 65
   recorded 2xx bodies, zero carry a credits, charge or cost field. Every ledger line
   is written `estimated_unverifiable`. A flat catalog price is a deterministic
   *estimate*, never a charge read back from a response.
5. **Fail closed.** A missing `gates.yaml` key reads as STOP, not as "no gate". A
   suppressed contact never reaches an output list. A CSV the reader cannot parse
   unambiguously is refused rather than silently dropped — a bare `\r` was once eaten
   by the reader while the writer quoted it, which let a suppressed address through.
6. **Evidence over vibes.** No speculating; claims carry a source line. Several tests
   exist purely to fail when a document asserts a number the code contradicts.
7. **`gtm/` is PII.** Gitignored, TTL-swept, erasable. `setup` refuses to run where
   `gtm/` is already git-tracked. A compliance sweep that cannot see the state tree
   holding the data refuses rather than reporting a clean sweep of the wrong one.

## Stack

Node >= 18.20.8 (the exact lowest version the suite has been run green on, not an
aspiration; CI pins that same version as its first matrix row). ESM
(`"type": "module"`), `node:test`, one runtime dependency (`yaml`).

`"type": "module"` means **every node executable needs a real `.mjs` extension** — Node
cannot load an extensionless file as ESM before 20.10, so an extensionless `bin/` entry
is dead across most of the supported range. `tests/contracts/executables-load.test.mjs`
enforces this, and spawns each executable through a symlink, because npm installs every
bin as one and a main-module guard that compares unresolved paths silently no-ops there.

Parse YAML with the JS library, never by shelling out to `yq`.

## Shared contracts

`_lib/contracts/*.schema.json` are **frozen**: content-hashed in
`tests/contracts/frozen-contracts.sha256` and checked on every run. Amending one is a
deliberate, announced change, not a patch — the procedure is in
[`CONTRIBUTING.md`](CONTRIBUTING.md). The pinned spec (`spec/openapi.yaml` and its
`.sha256`) is read-only in the same way; it is regenerated by the catalog tooling.

## Definition of done

Code, plus the change's stated verification criterion as an executable `node:test`.
A change without a passing test that would fail against the old behaviour is not done.
